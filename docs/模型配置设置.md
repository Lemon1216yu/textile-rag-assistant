# 在界面中配置模型

使用管理员账号登录 http://127.0.0.1:8766 ，进入左下角 **工作空间管理 → 模型与服务**。

## 对话模型

填写模型名称、Base URL 和 API Key。支持 OpenAI Chat Completions 兼容协议，包括百炼兼容接口；不代表兼容所有供应商的原生协议或 Responses API。

例如百炼北京区域可先点击“阿里云百炼”，再按自己的模型授权、区域和控制台地址修改。Base URL 填到 `/v1`，程序自动添加 `/chat/completions`，不要重复添加请求路径。

高级参数支持 Temperature、最大输出 Token、请求超时（5–60 秒）和 JSON 模式。路由和摘要有独立的较小输出预算。若服务不接受 `response_format`，可关闭 JSON 模式参数；服务仍需按指令输出合法 JSON。

先点 **测试连接**，检查响应格式；再点 **保存配置**。测试发送合成内容，不发送企业问题、文档或对话历史，可能产生少量服务商费用。测试成功不能代表业务准确率或所有模型能力都验证通过。

## Embedding 与 Rerank

- Embedding 使用 `/embeddings` 兼容接口，必须填写服务支持的维度。当前请求发送 `dimensions` 参数。
- 有已建立的向量索引或正在处理的文档时，禁止直接修改 Embedding 模型、地址和维度。密钥轮换不受此限制。更换向量空间需要运维迁移索引，本界面不会冒险覆盖旧向量。
- 首次启用 Embedding 后，之前用原文模式导入的资料没有向量，需上传新版本以完成索引。不会悄悄产生整库重新向量化的费用。
- Rerank 支持百炼 `input/parameters` 格式及 `query/documents` 兼容格式。填写完整请求 URL；百炼地址可能包含业务空间 ID，快速填写不会猜测这个 ID。`qwen3-rerank` 对应兼容格式，其他模型需按官方接口确认。

参考：[百炼重排官方接口](https://help.aliyun.com/zh/model-studio/text-rerank-api)。

## 生效方式与密钥

设置作用于整个单企业工作空间，只有管理员可以读取配置详情、保存或执行连接测试。成员无权调用这些接口。保存还需通过现有 CSRF 校验。

配置保存后，新问答和下一次索引任务读取新配置；正在处理的请求保留自己的配置快照。无需重启 API 或 worker。并发管理员保存时会检查版本，后到的旧版本保存请求会明确报冲突。

API Key 仅在输入时提交给本工作空间服务器，查询配置永远只返回是否已配置。留空表示保留，输入表示替换；清除需要勾选并保存，生产模式不允许因此缺少必需服务。更换接口地址时，必须重新输入或清除旧密钥，避免把原有密钥转发到新服务。

持久化文件为 `UPLOAD_DIR/.model-settings/settings.enc`，整体通过 Fernet 加密并原子替换。配置损坏或加密密钥丢失时明确失败，不回退到其他密钥继续请求。

部署时优先设置独立的 `MODEL_CONFIG_ENCRYPTION_KEY`（Fernet URL-safe Base64 32 字节密钥）；新的部署生成脚本会生成它。旧部署和本机开发环境没有该变量时，首次保存自动生成权限受限的 `encryption.key` 文件。Windows 文件实际保护还取决于目录 ACL。不得在已有加密配置后随意更换加密密钥；轮换需先完成解密迁移。

现有备份脚本会把 `.model-settings` 随原文目录一起备份。使用文件密钥的环境会同时备份密钥，因此备份必须限权并加密；使用环境变量密钥时，应通过独立密钥管理流程保管它。此实现不是 KMS，也不宣称能防御已获得服务器文件权限的攻击者。

没有使用浏览器 localStorage 保存模型密钥，审计记录只保存修改的字段名和密钥动作，不保存密钥值。

## 验证

新增测试覆盖加密/不回显、密钥保留与清除、不同实例重新读取、真实问答调用使用新模型参数、worker 动态加载、向量索引变更保护、地址更换密钥保护、权限/CSRF、版本冲突、合成连接测试及损坏配置失败关闭。真实百炼连接仍需要实际密钥，不用模拟测试宣称服务已连通。
