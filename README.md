# 织知 · 纺织企业知识助手

面向面料规格、工艺记录和业务指引的 RAG 应用，围绕“查到正确资料、只看授权版本、回答能够核对”实现文档建库、混合检索、引用溯源和知识维护工作台。

这是结合纺织制造场景开展的**个人学习与实践项目**，使用模拟业务资料与公开技术 PDF，可在本机运行。未接入真实企业系统，未作为企业生产系统交付。

**[界面与作品介绍](https://lemon1216yu.github.io/ai-portfolio/#rag)** · **[设计与实现](docs/RAG设计与实现.md)** · **[操作手册（下载后浏览）](使用说明.html)**

## 从一个实际问题出发

跟单需要回答“C240 的克重和有效幅宽是多少”，研发需要核对工艺条件，知识维护人员需要更新规格书。除了找到相似文本，还需要解决编号匹配、旧版资料、部门可见范围和无依据回答的问题。

员工提问后，系统只检索有权访问的已发布资料，返回答案或原文摘录，同时展示文档、版本、片段和 PDF 页码；维护人员可以上传、检查切片、重新索引，交由管理员审核发布。

## 已实现的主要能力

| 环节 | 当前实现 | 解决的问题 |
| --- | --- | --- |
| 文档入库 | PDF 按物理页解析，保留章节；默认 400 字符切片、56 字符重叠；后台索引 | 保留正文出处，便于复核 |
| 知识维护 | 上传、切片预览、重新索引、审核发布、版本替换 | 上传成功不等于可以用于回答 |
| 混合检索 | BM25 + 向量召回、RRF 融合、MMR、去重与 Rerank | 兼顾面料编号、专业术语和自然语言描述 |
| 访问控制 | 部门、发布状态、面料过滤；返回前及历史阅读时复核权限 | 防止越权资料或失效版本被再次展示 |
| 会话处理 | 条件提取、上下文补全、近期轮次、事实条件与摘要 | 支持“它的缩水率呢”，减少面料条件混用 |
| 答案与分流 | 引用、证据不足提示、条件澄清、人工工单 | 明确知识查询与审批决策的边界 |
| 过程查看 | 改写问题、召回数量、精排分数、来源 | 定位资料、召回和排序问题 |

## 两条核心链路

```text
建库：上传 → 解析 / 分段 → 向量编码 + BM25 索引
     → 检查切片 / 调整重建 → 审核发布
问答：问题 + 会话条件 → 路由 / 澄清 / 查询补全
     → 授权范围 → BM25 与向量召回 → RRF → MMR / 去重
     → Rerank → 证据筛选 → 摘录或带引用生成 → 权限复核 / 审计
```

链路使用 LangChain Runnable 组合，重点是可检查的 RAG 流程与文档管理，尚不具备自主操作企业系统的能力。

## 技术选型与运行方式

后端使用 Python、FastAPI、SQLAlchemy，前端为 React 工作台。关键词索引使用 SQLite FTS5 BM25；本地模型使用 BGE-small-zh-v1.5 与 BGE-reranker-base 的 ONNX 版本。

| 方式 | 配置与用途 |
| --- | --- |
| 本地检索 | SQLite 元数据与向量、本地 ONNX Embedding / Rerank；适合小语料复现。未配置生成模型时明确展示原文摘录 |
| 模型服务 | 可配置对话、Embedding、Rerank 服务；更换编码模型需要重建向量，精排阈值不能跨模型直接复用 |
| 外部基础设施 | 提供 MySQL、Redis、Milvus、Docker / Nginx 配置与联调记录，不等同于企业生产部署 |

详见 [离线运行说明](docs/离线RAG运行说明.md)、[模型设置](docs/模型配置设置.md)、[部署手册](docs/企业版部署与验收.md)。

## 本地启动与第一次验证

准备 Python、Node.js / npm 和 PowerShell。首次需要联网安装依赖、下载模型与公开 PDF。

1. 首次将 `.env.enterprise.example` 复制为 `.env.enterprise`，已有配置请保留。
2. 在 `.env.enterprise` 设置 `LOCAL_RAG_MODELS=1`，启用本地向量与精排。
3. 在项目目录执行：

```powershell
.\start-enterprise.ps1
```

打开 **http://127.0.0.1:8766/**，开发账号见 `tmp/enterprise-access.txt`。GitHub Pages 提供展示页面，实际问答需要启动本地服务。

| 操作 | 观察什么 |
| --- | --- |
| 问“C240 的克重和有效幅宽是多少？” | 模拟规格书中核对 240±10 g/m²、148±2 cm，查看版本与出处 |
| 追问“它的缩水率呢？” | 检查改写是否继续使用 C240，核对来源 |
| 问“丝绸制丝废水主要有哪些污染物？” | 查看公开技术 PDF 的证据、物理页码和检索过程 |
| 上传 LY317 模拟规格书 | 对比上传前、索引后未发布、审核发布后的检索状态 |
| 问“这个批次可以直接出货吗？” | 应转人工工单，不能直接作出放行结论 |

LY317 操作见 [手动验收清单](手动验收/验证步骤.md)。面料资料为模拟数据；公开 PDF 是技术参考资料，不是企业内部 SOP。

## 如何评价效果

仓库保留 [固定题集](examples/retrieval_cases.json) 与 [逐题结果](docs/retrieval-evaluation.json)。以下为**已存档的小样本检索结果**，并非本次重新运行，也不是生产准确率。

| 方法 | 可回答题数 | Hit@6 | MRR@6 | 无答案题正确拒回 |
| --- | ---: | ---: | ---: | ---: |
| BM25 | 9 | 1.000 | 0.926 | 1 / 1 |
| 完整混合链路 | 9 | 1.000 | 0.944 | 1 / 1 |

两种方式都命中了 9 道可回答题；混合链路把其中一题的目标从第 3 位排到第 2 位。这个结果仅说明当前样本上的排序差异，不能证明真实业务中的稳定提升。无答案题只有 1 道，也没有评价生成正确性、查询改写或用户任务完成率。

在已初始化且启用本地模型的环境中复现：

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_enterprise
```

输出为 `tmp/retrieval-evaluation.json`。下一步应补充近似编号、版本冲突、跨部门、缺少条件和无答案题，分别统计检索命中、引用一致性与拒答表现。工程验证历史与待验证项见 [验收记录](docs/企业版验收记录.md)。

## 代码入口与限制

- [enterprise/ingestion.py](enterprise/ingestion.py)：解析、切片与索引任务。
- [enterprise/lexical.py](enterprise/lexical.py)：持久化关键词检索。
- [enterprise/rag.py](enterprise/rag.py)：路由、权限、检索、回答与会话。
- [enterprise/local_models.py](enterprise/local_models.py)：本地向量与精排模型。
- [enterprise/providers.py](enterprise/providers.py)：模型服务与基础设施适配。
- [frontend/](frontend/)：问答、知识库、工单与管理页面。

扫描 PDF 需要另行 OCR；复杂表格与图片没有完整结构恢复保证。本地向量方案面向小语料，尚无大规模并发验证。ERP、企微、SSO 和真实业务数据尚未接入。后续优先补业务标注集和失败案例，再确定 OCR、切片与系统集成需求。

旧版 `app/`、`static/` 使用 8765，与当前工作台身份和数据机制不同；体验请以 `enterprise/`、`frontend/` 的 8766 为准。
